# Working on Proto-Mind

Proto-Mind is a personal macOS application with a Python cognitive core. The goal is a dependable, useful daily assistant that can grow substantially in capability.

## Engineering direction

- The operator explicitly authorized autonomous improvements on 2026-09-04. Use engineering judgment to fix defects, simplify workflows, refactor architecture, add worthwhile dependencies and revise these project instructions. Routine work within that direction does not need repeated approval.
- Choose priorities from user value and current evidence. Historical milestone order, narrow pilot limits and earlier implementation choices are not permanent design constraints.
- Keep product behavior and controls honest: distinguish a completed model response, saved data and a verified task outcome. Preserve user data and make intentional changes to permissions, memory policy or schemas understandable and recoverable.
- A clean Git commit or branch point is a sufficient source checkpoint for code-only work. Back up affected personal state before a migration or operation that can alter it; a new full archive is not required for every patch.
- Core-memory read/change/save operations must hold `MemoryStore.transaction()` through revalidation, save and verification. Keep live sidecar locks in place; plain reads and previews must remain free of writes. New Native project decisions/facts carry `context_scope`; preserve old unscoped records without migration. Automatic supersession requires one explicitly named prior decision in the same scope, never generic tag overlap.
- Native dialog writes must hold the persistent `.history.lock`, compare the loaded manifest with current bytes, and publish immutable conversation objects before the atomic manifest. Preserve current and in-window data before recovery; never treat dialog-only exports as a complete private-state backup.
- Tests and fault injection should use disposable state. Run focused checks while iterating and the broader suites appropriate to the affected components before delivery. Match verification claims to what actually ran.

## Project map

- `native/Sources/`: primary SwiftUI/AppKit application. `AppModel` owns shared state and is the sole dialog-history writer; `ConversationExecution` owns each conversation's reusable bridge, live output, exact request and update queue. Capture that execution before awaiting; background completions must not mutate the selected editor or navigation. Metadata/quotas use the independent `serviceClient`; task-bound core workflows stay on their conversation's bridge. `globalBusy` guards shared recovery/authentication, while `busy` reflects the selected task or a shared operation; `ConversationModel`, `TurnExecutionModel`, `WorkSessionHistoryModel`, `SessionSpineFlowModel` and `HistoryPersistenceModel` group its flows. `ChatStore`, `ChatHistoryFiles`, `ChatHistoryFormat` and `ChatBackups` own dialog persistence.
- `WorkspacePresentations` routes auxiliary screens and nested confirmations inside their originating window. Each companion owns a local stack registered with the main router; forwarded pages retain their source bindings, updates and dismissal guards. Capture the presentation destination before awaiting; OS file pickers attach to that captured window. Keep the underlying chat/tab mounted. Voice and the two optional `DesktopCompanionWindows` have independent windows. `DesktopPresentation` owns the floating workspace and nonactivating core. Companions are available in normal and cube modes, retaining the same windows, `WorkspacePanelModel` and local presentations across mode changes. Use normal window levels outside cube mode; normal minimization/closing hides the group without clearing enabled preferences. Attached expansion respects the measured regular detail column and native content-layout rect. Companions retain their own `WorkspacePanelModel` across docking, expansion and hiding; geometry, visibility and separate glass preferences are UI state, never task ownership. Attached windows keep fixed upper/lower slots in a vertical column with small gaps and a persisted height split. Reattachment and the return-to-position action reset the column width and split; content-derived hosting constraints must not resize these slots. AppKit parent/child ownership and native window dragging move the attached group together; position notifications must not reposition its children. Custom companion/core drags use event-captured global coordinates, never coordinates recomputed through an already moved window. Detach/hide/shutdown remove that relationship; detached compact/expanded sizes stay independent, while moving a miniature translates its saved expansion and a new detachment rebases it locally. Explicit main presentations clear covering expansions and raise their owner. Cube hover and folding show/hide both attached and detached windows by default; an explicit UI preference may keep detached windows visible. Prepare the complete window group before showing it; animate its opacity in one AppKit context and retain child ownership until the shared fade finishes. Cancel prior alpha animations before reopening or leaving floating mode. Focus/order notifications never pin previews: use intentional input in an owned window. Preview-only pointer checks recover missing tracking exits and stop on pin/hide/shutdown. Presentation never changes task lifetime or permissions. Keep SwiftUI's titled frame/toolbar ownership intact. Desktop preferences remain separate from private-state backups.
- `ResponseAttention` stores exact unread response IDs in profile-namespaced UI preferences, separate from history and private backups. Register new replies/errors through the completion append path; never infer unread state for old history. Acknowledge only the exact visible response footer in an active reader. Hidden tabs, covered presentations and passive cube previews must not clear markers. Cube counts and task-running animation are independent; interrupted requests are not successful outcomes.
- `WorkspacePDFView` displays bounded PNG pages from `PDFPageReader` through the independent service client. `native_pdf.py` and the sandboxed `PDFHelper` bind image/text to the original source hash, preserve crop/rotation and limit each raster to 1600 pixels per edge. PDF originals are parsed only in the helper. Rendering does not attach content, mutate history, acquire tool access or follow PDF actions. Explicit paperclip selection still sends only the chosen page text through the existing metadata contract.
- `SidebarView`/`SidebarMenuView`, `ConversationWelcomeView`, `ComposerView` and `NativeSettingsView` own everyday UI; `WorkspaceView` composes the workspace/transcript and `NativeTheme` defines adaptive appearance. `WorkspacePanels` owns two equal transient surfaces; `WorkspacePanelModel`/`WorkspacePanelView` retain their file/browser/conversation/terminal tabs. Capture the destination panel before awaiting. `ConversationPaneModel`/`ConversationPaneView` route drafts, send and stop through the same AppModel and per-conversation executions, never a second history writer. Main and side conversations share `ChatView`/`ComposerView` through `ConversationComposerContext`; bind controls, dictation, previews and criteria to exact conversation IDs. `ConversationRouting` selects the sidebar destination from intentional input in workspace content, never pointer hover or window-order notifications. Keep the main selection unchanged when opening a side tab, preserve non-chat tabs, and fall back to main only when the chosen surface is unavailable. Panel launchers stay provisional until first Send: exclude untouched drafts from the archive and all conversation lists, but preserve written drafts/attachments for restart and expose them when their last editor closes. `WorkspaceTerminal` owns the SwiftTerm PTY until explicit close or shutdown; hidden/expanded surfaces must retain sessions and release hidden keyboard focus. `BrowserView` owns manual WebKit navigation. `WorkspacePanelChrome` hides only compact companion headers on pointer exit; keep tab content mounted, retain temporary field/menu/drag holds, and clear them when a window hides. Expanded windows and ordinary workspace panels retain their controls. Keep source evidence and permission state reachable when simplifying presentation.
- `ModelAPIConnections` stores nonsecret API profiles in namespaced UI preferences and destination-bound credentials in Keychain; neither key nor credential-bearing RPC parameters belong in history, logs or exports. `native_api.py` supports Responses/Chat Completions turns with core memory and selected context. Explicit per-chat PM-tool opt-in uses `native_api_tools.py`; preserve completed function-call IDs and opaque Responses reasoning state, stop owned connections, and never retry uncertain actions or paid requests. Codex retains Full Mac and live steering; API does not silently enable Brother Persona.
- `ClaudeConnection` uses the official, unmodified Claude Code auth flow and a separate `claude-profile`; never extract, proxy or copy its credentials into PM stores. `native_claude.py` owns one isolated SDK worker/process group per turn, reusing PM memory, context and history. Claude plain chat disables tools; Full Mac requires the same fresh conversation grant and exact-turn workspace checks. Provider changes revoke access. `native_claude_sessions.py` binds exact durable SDK sessions to conversation/account/workspace/access/tool mode and private-restore generation. Hold its persistent per-conversation lease through the confirmed result; incomplete sessions never authorize automatic retry/resume. Claude Code keeps a session's first system prompt on resume: keep per-turn memory/Observer context in the turn message, and bind sessions to the system-prompt hash. Failed requests stay in provider history behind `Conversation.incompleteRequestMarker`, which the continuity hash skips. Local bootstrap is bounded to 300,000 Unicode characters / 2,000 messages with explicit omissions, without a per-message cap. Session records and provider rollouts stay outside private backups. Claude still has no live steering or Brother Persona. `ClaudeAccountModel` observes catalog/quotas independently of task state. `native_claude_metadata.py` reads initialization and the pinned CLI get_usage control message in a bounded, no-query worker; keep account revalidation, missing/stale quota semantics and exact resolved model IDs. Never replace this with credential extraction or an OAuth proxy. Auth changes wait for Claude tasks to finish. `requirements-claude.txt` pins SDK dependencies in a separate interpreter; portable packaging preserves Anthropic's binary and signature. See `CLAUDE_CONNECTION.md`.
- `CodexAccounts` binds each conversation to an optional account UUID; nil preserves the original login. Capture that UUID when creating its execution/metadata bridge. Each extra login owns `codex-accounts/<uuid>/codex-profile`, a model catalog and a quota cache; account names/IDs are UI preferences, credentials never enter backups. Durable provider bindings live under `codex_account_threads/<uuid>` and lose authority on private restore, just like the main registry. Sign-in/out closes only idle bridges for that account. Changing a chat's account preserves its messages but clears model/access and persists a pending local session reset; clear it only after exact-binding reset and history save succeed, before sending to the provider. Main, companion, voice and Telegram inputs share this rule. This separates provider accounts, not the app's shared memory or local user data.
- `MessengerConnections` gives Telegram/WhatsApp distinct persistent WebKit stores by profile/service; ordinary browser tabs remain ephemeral. Messenger-to-task capture requires an explicit selection. Reset closes all matching tabs before clearing data. `TelegramRemoteModel` accepts only fresh direct private messages from the locally paired owner, for an explicit task allowlist. Keychain holds the bot token; `TelegramRemoteStore` keeps pairing/cursor metadata outside restored backups, with a persistent exclusive lease and durable cursor advance before command processing. Never log credential-bearing URLs or retry an uncertain send/action. `sendExternalTaskMessage` shares the voice execution path, preserves drafts and rechecks remote authorization after preparation. Results are routed by conversation/source through the ordinary completion save; disconnect/revocation suppresses future replies without cancelling accepted work. New remote conversations never inherit Full Mac selection. Tests use fake Telegram transports and disposable profiles, never live credentials.
- `BrowserContext` captures explicit bounded page/selection text in WebKit's isolated world and revalidates navigation before delivery. Preserve the exact URL, partial marker and untrusted-source boundary through the existing user-message/steering pipeline. Draft handoff preserves existing text and attachments; voice routes exact browser/conversation IDs without consuming the editor. `WorkspaceAnswerPreview` is a transient document bound to its original conversation. `NativeLocalization` and the two `NativeEnglish` catalogs apply a profile-specific RU/EN language live through shared observation. Keep existing windows, tasks, tabs and drafts mounted; native window titles and transient popups follow the language notification. Translate literal UI templates with `L10n.text`/`L10n.format`, never persisted user text, provider identifiers/output or exact protocol confirmation tokens. Interpolation values remain verbatim. macOS-owned controls follow the system language.
- `WorkspaceAgentTools` and `native_workspace_tools.py` bind model-to-PM calls to the exact running conversation, request, provider/account/project and current permission generation. Full Mac uses explicit contract v3; API tools require per-chat opt-in, invalidated by private restore. Keep native history writes inside AppModel. Task-owned metadata workers and MCP transports close on Stop/disconnect; queued mutations cannot begin after EOF. Never log tool arguments/results or credentials in journals. `WorkspaceAgentBrowser` uses observed elements in WebKit's isolated world, consumes snapshots on action, and rejects stale targets. Messenger automation stays selection-only. `WorkspaceServices` owns explicit stdio/Streamable HTTP connections with Keychain credentials and observed tool catalogs. Preserve each task-owned MCP session between calls, isolate conversation owners, and close even idle transports/catalogs at turn completion. Failed sessions cannot reconnect or replay automatically. `native_documents.py` uses bounded project readers and atomic create-only writes; Quick Look presents Office artifacts and the PDF helper supplies page images. Isolated tasks use `native_worktrees.py`; they start at committed HEAD and never auto-merge/delete. Mac delegation is session-only, grants one child turn, and is not recursive. Structured questions persist in their conversation; a late answer is new input, never approval for an expired call. Continuation requires a user action.
- `proto_mind/`: Python cognition, persistence, provider adapters and stdio bridge. `native_history_routes.py` groups journal/Spine RPCs; `native_chat_history.py` adapts exact v6 dialog evidence without writing it.
- Computer Use cleanup gives only the verified signed helper its installation `CODEX_HOME`; the Codex server keeps Native's private profile. Await the scoped `turn-ended` command through the live Codex parent before closing it, including Stop/failure paths. A zero exit under the wrong installation home can be a no-op; an unconfirmed release must remain visible. Do not kill the shared desktop service or clear the saved Full Mac selection to end a task.
- Project-note workflows live in `ProjectMemoryModel`/`ProjectMemoryView`, `native_project_memory.py` and the pure linked-state projection in `native_project_note_state.py`. Removal excludes future selection and retains history; it is not provider-history erasure. Automatic recall and library search share `project_recall_search.py`; `evals/project_recall/` holds the fixed local quality corpus. New Native clients request v3 recall explicitly; preserve v1/v2 readers and the legacy-client request default while Native and the Python source can be updated separately.
- `ConversationHistory`/`ConversationHistoryView` search saved dialog text without a provider call. Exact continuation uses `WorkSessionHistoryModel` and existing run/turn references; transcript destinations are transient, with bounded message neighbourhoods in `WorkspaceView`.
- `PrivateBackupModel`/`PrivateBackupView`, `native_private_backup.py` and `native_private_restore.py` own full private-state copies and explicit recovery. Keep the Native namespace inventory aligned when adding stores. Restore markers block ordinary operations; generation markers prevent pre-restore instances from writing stale state. `CodexUsageModel`/`CodexUsageView` and `native_codex_usage.py` read subscription metrics without model turns. Compact and full account-usage reads, exact live steering and bounded local attachment previews use independent queues; ordinary operations stay serial within each bridge. Work-session writers hold the shared restore barrier plus exclusive conversation/run locks; Codex thread registry updates use a persistent cross-process sidecar lock. Keep their independent ownership and bounded request routing. Explicit earned resets use `native_codex_reset.py`; persist the account-bound attempt key before consumption and reuse it after uncertainty. The reset journal stays outside restored backups.
- `TaskUpdates.swift`/`native_steering.py` bind text and selected attachment updates to the active main Codex turn. Attachment readers retain the original workspace/protected roots and revalidate selected hashes before sending; previews never send model input. Queue entries and delivery states live inside the original user message, preserving exact turn adjacency. Persist before sending; uncertain delivery is never automatically retried. Selector turns must not expose steering. `PublicMessages` separates answers across user-input boundaries.
- New Native Full Mac clients explicitly request agent contract v3 with PM workspace tools: no total turn-duration or activity cutoff. Keep v1/v2 historical readers and the old-client request default. Recent public previews are bounded independently of execution; trimming must be marked partial, must preserve exact input/contracts/lineage and must never remove tool rows already referenced by a completion snapshot. RPC/tool deadlines remain distinct from the lifetime of a task.
- `native/Tests/` and `proto_mind/tests/`: Native checks and Python regression tests. `test_flow.py` is the stable aggregate for `test_flow_*.py`; shared fixtures live in `flow_fixtures.py`. Add flow tests to the relevant topic module and keep the aggregate/provenance inventory aligned.
- `scripts/test_native.sh`: builds Native and checks it against temporary Python fixtures.
- `LiveVoiceModel`/`LiveVoiceTransport`/`LiveVoiceAudio` own the explicit GPT Live API call; `LiveVoiceProtocol` validates completed Responses function items and `LiveVoiceTools` routes commands through captured conversation executions. Voice input must preserve editor drafts/attachments. Hanging up stops audio, not accepted tasks. `LiveVoiceKeychain` keeps credentials outside state/backups; ordinary tests never call the API. `PersistentAgentAccess` remembers only conversation/workspace selection in preferences v3 and issues fresh bridge tokens; restore clears the selection.
- `DictationModel`/`DictationSpeech` insert Apple Speech results into the captured composer draft; never auto-submit or let late results overwrite manual edits or another conversation. Use utterance delegate boundaries to retain completed speech separately from the revisable partial; Apple may reset `bestTranscription` after a pause without ending the task. Dictation and GPT Live own the microphone exclusively. `SidebarProjectOrder` and dictation-language selection use profile-namespaced macOS UI preferences, separate from history and permission stores.
- `scripts/run_tests.sh`: Python tests and compile checks using the project Python selector.
- `scripts/build_native_app.sh`: local application bundle in `dist/Proto-Mind Native.app`. The operator's app runs from that bundle and loads Python from this checkout, so a new conversation bridge picks up working-tree edits immediately. Never rebuild over a running app: set `PROTO_MIND_NATIVE_OUTPUT` to a staging bundle, verify it, then swap bundles by rename and keep the previous one.
- `scripts/build_portable_app.sh` / `scripts/package_native_app.py`: separate Apple Silicon distribution with pinned Python/Codex runtimes. `LaunchConfiguration.codeRoot` is installed source; `projectRoot` is mutable core storage. Portable `ProtoMind/core` and `ProtoMind/native` are sibling namespaces outside the bundle. Preserve the developer installation, use `--profile-root` for disposable QA, and never copy operator state into a release. `INSTALL_MACOS.md` and `native/Distribution/README.md` describe first launch and the Apple signing gate.

`README.md` describes current behavior; `PROTO_MIND_EVOLUTION_ROADMAP.md` is the current priority map; `NATIVE_MACOS_ROADMAP.md` records Native releases. `PROTO_MIND_ARCHITECT_LEDGER.md` provides architectural context and historical evidence. `CODEX_COLLABORATION.md` and contest documents describe the earlier Build Week submission, not the current development policy.

Prefer a small, current source of truth over copying release narratives across documents. Native is the primary interface; older interfaces can be retained, simplified or retired with an intentional transition.
